# v0.5.7 - the sync that could never end

Reported as "synchro a l'infini et ne fonctionne pas": the popup sat on
"Transferring & verifying…" while nothing moved.

## What was actually happening

The relay holds ONE persistent CDP connection to Lightpanda (the cookie jar is
scoped per connection, by design). Lightpanda runs in WSL - and WSL restarted
under the relay at some point today. The WebSocket died.

The proxy route (`/v1/cdp`) has always recovered from that: on a dead socket it
resyncs and retries. The import route did not. So every `/v1/session/import`
failed in ~0ms with `WinError 10053` at the storage-verify step, and the only
thing that ever revived the socket was, by chance, some other component using
the proxy first. Measured live: import 400/10053 -> proxy call -> import 200.

## The fix

- `set_session()` now does exactly what `proxy_cdp` has always done: resync and
  retry once on a lost connection. `tests/test_import_resync.py` reproduces the
  dead socket and fails against the old code (verified by reverting the fix and
  watching the test go red).
- The popup puts a 30s deadline (AbortController) on the import fetch. A client
  that waits forever has no honest state to be in - "still working?" is not a
  status. Now a stuck relay ends in 30s with `errRelayTimeout` ("Relay did not
  answer within 30s (Lightpanda restarting?). Try again."), translated in all
  ten languages.

## Verify it yourself

Live proof of the whole path, same payload as the popup: import after a relay
