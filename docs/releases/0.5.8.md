# v0.5.8 - the socket that died mid-injection

v0.5.7 added resync+retry to the import path. The gate and the field said:
still broken - the popup showed "Transfert incomplet : 0/8 clés localStorage
reçues par Lightpanda (manquantes: <verify failed: [WinError 10053] ...>)".

## What v0.5.7 missed

`_inject_storage` wraps its evaluate loop in `try/except Exception`. When the
CDP socket died *during* the localStorage injection - not before it - the
connection error was caught right there, turned into a fake "missing key"
named `<verify failed: WinError 10053>` and swallowed. Two consequences:

1. `set_session` never saw an `OSError`, so the resync added in 0.5.7 could
   not trigger. The retry only covered a socket that died *before* the apply.
2. The raw localized Windows sentence ("Une connexion établie a été abandonnée
   par un logiciel de votre ordinateur hôte") rode along in `storage_missing`
   and was rendered verbatim in ten languages that never translate an OS.

## The fix

- `websocket.WebSocketException` and `OSError` are re-raised by the injector:
  a lost connection is a connection error, not "keys missing". `set_session`
  resyncs and redoes the whole import, exactly as it already did when the
  socket died before the first call.
- Page-level evaluate failures keep their retry (fresh navigation) but record
  a short code (`verify-error:ExceptionName`). These strings reach the popup
  verbatim; they must be codes, never OS prose.

## Proof

`tests/test_import_resync.py` now has four tests. The two new ones were run
against the reverted code: red (2 failures), then green with the fix - a test
that cannot fail is decoration. Live: 12 cookies + 8 localStorage keys import
in 1.6 s through the real relay, with a forced resync in the loop.
